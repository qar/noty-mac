# Noty v1.4.2

修复同一项目目录中多个 Codex 客户端的提醒无法确定来源窗格的问题。

## 相对 v1.4.1

- 使用线程对应的实际客户端定位原 tmux 窗格，不再仅靠项目名称和分支区分同目录的多个 Codex。
- 新收到的本地提醒会在后台保存已核实的来源。已有线程 ID、但缺少 pane 的历史提醒也可在点击时恢复来源。
- 原生子代理和 headless exec 保存可核实的原始线程 ID，减少子代理退出后丢失来源的情况。
- 跳转前再次核对客户端。连接失效、来源变化或仍有歧义时保留提醒；跳转成功后才自动标记已读。
- 继续跳回原窗格，不新建 Codex 标签，也不要求用户手工维护线程与窗格的对应关系。

## 安装与升级

- 已安装的应用可通过“检查更新”下载 `1.4.2`，完成下载后安装并重启。
- 发布包含应用内更新使用的自包含 `app.asar`，以及完整安装包 `Noty-1.4.2-arm64.dmg`。
- 安装包适用于 Apple Silicon，沿用 ad-hoc 签名，未做 Apple 公证。
- 原有通知、已读状态、订阅和设置继续保留。

## 相对修复验证构建

- 修复逻辑与 PR #20 的独立验证构建一致。
- 正式版本号提升为 `1.4.2`，现可通过应用内更新获取。

## 已知限制

- 精确线程定位需要 Codex 提供现有的客户端归属接口。旧协议或其他 agent 仍沿用原有来源校验与唯一候选恢复。
- 客户端已退出、连接失效或来源无法核实时，提醒会保留，不会猜测其他窗格。
