# Noty v1.4.0

本版将本机 AI 提醒改为 SQLite 本地投递，并统一提醒标题。Plane 继续通过 ntfy 接收。原有通知、正文、元数据和已读状态会自动迁移。

## 相对 v1.3.0

- 本机 AI 提醒直接写入 SQLite，无需经过外网。Noty 退出期间也能保存，启动后补收。
- 通知与设置分开存储。已读和收起操作按记录更新，后台补充 Plane 信息不会覆盖刚做的操作。历史记录不再截断到 1000 条。
- 新增本机通知来源和 `noty-notify` 命令安装入口。保留显式选择 ntfy 的远端发送方式。
- 主窗口和托盘支持 Vimium 风格的键盘操作。输入框、中文输入和批量操作确认保留原有行为。
- Tmux 提醒统一显示“AI 通知”，不再按 agent 名称重复显示标题和来源；原始来源信息仍用于跳转。
- Plane 回复预览只显示新增评论，跳过被引用的旧评论。完整原文仍可展开查看。
- 原 checkout 切换 Git 分支后，没有精确匹配时，可恢复到同项目中唯一可核实的原 agent 窗格。多个候选仍拒绝猜测，跳转失败时保留提醒。

## 安装与升级

- 安装包适用于 Apple Silicon，采用 ad-hoc 签名，未做 Apple 公证。
- 完整安装包为 `Noty-1.4.0-arm64.dmg`。发布同时提供应用内更新使用的 `app.asar` 和 `SHA256SUMS`。
- 首次升级会先备份旧通知，再事务导入 SQLite。订阅和其他设置保持不变。
- 本机通知需让发送端使用 `noty-notify`。在“设置 > AI 集成”安装命令，再让已有 hook 转发给该命令。应用不会自行修改 PATH、shell 或 agent 配置。旧 ntfy 订阅仍兼容。
- 需要从其他机器发送时，使用 `NOTY_TRANSPORT=ntfy`。独立脚本需要把发布附件中的 `notification-schema.sql` 放在脚本旁，并安装 `jq`。
- 发布包含的 SQLite 模块和通知脚本均位于 `app.asar`。应用会同步自己的本地工具副本，兼容后续应用内更新。

## 相对上一份本地包

- 正式版本号更新为 `1.4.0`。
- 使用最新 `develop` 中已合并的代码构建正式安装包。
- 继续包含已安装本地包中的 SQLite 通知、统一标题、Plane 评论预览和 tmux 恢复修复。

## 已知限制

- 多个 Codex 客户端共用同一 checkout，且没有可靠的任务与窗格绑定时，子代理提醒仍可能无法唯一定位。此时保留提醒并提示失败。
- tmux 重启后，部分历史提醒的会话名称可能不准确；点击时会再次校验来源。
- Plane 事件重要性过滤尚未提供，目前保留收到的全部提醒。
