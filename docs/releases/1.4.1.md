# Noty v1.4.1

修复普通目录中的 AI 提醒无法跳转到 tmux 来源窗格的问题。

## 相对 v1.4.0

- 来源窗格仍然存在时，不再因为项目目录不是 Git 仓库而拒绝跳转。
- 原 pane 编号失效后，可以恢复到来源目录中唯一可确认的窗格。
- 首次定位、来源恢复和跳转前复核使用同一套校验。多个候选、目录变化和 Git 查询异常时保留提醒，避免误跳。
- 提醒仍只在跳转成功后自动标记已读。

## 安装与升级

- 已安装的应用可通过“检查更新”下载 `1.4.1`，完成下载后安装并重启。
- 发布包含应用内更新使用的 `app.asar` 和完整安装包 `Noty-1.4.1-arm64.dmg`。
- 安装包适用于 Apple Silicon，沿用 ad-hoc 签名，未做 Apple 公证。
- 原有通知、已读状态、订阅和设置继续保留。

## 相对上一份本地修复构建

- 正式版本号从 `1.4.0` 提升为 `1.4.1`。
- tmux 普通目录跳转修复与上一份本地构建一致，现已进入正式发布。

## 已知限制

- 多个 agent 共用同一来源目录，且没有可靠的任务与窗格绑定时，部分历史提醒仍无法唯一定位。此时继续保留提醒并提示失败。
